# 非同期永続世界ゲーム

サークル向けの非同期・永続世界ゲームです。**GitHubのIssueにコメントで命令を書くと、1日4回（9/13/17/21時JST）自動でターンが進みます。** すでに動いています。

- **盤面（誰でも見られます）**: <https://kya6-tomato.github.io/C3-mini-world-game/>
- **遊び方**: このリポジトリで自分専用のIssueが立ったら、そこにコメントを書くだけです。書き方は [コメントの書き方.md](コメントの書き方.md)、ルールの中身は [ルールブック.md](ルールブック.md) を見てください。

---

## 1. 遊ぶ側の人（部員）向け

1. 自分専用のIssueを探す（無ければkya6に連絡ください）
2. [コメントの書き方.md](コメントの書き方.md) を見ながら、今ターンにやりたいことをコメントする
3. 1日4回（9/13/17/21時）で自動的に反映され、結果が同じIssueに返信される
4. 何もコメントしなかった場合は、いつもの行動（常設命令）が自動で続くので、書き忘れても大丈夫です
5. 盤面（地図・順位・ログ）は <https://kya6-tomato.github.io/C3-mini-world-game/> でいつでも見られます

ルール（資源の意味・行動の一覧・信用の仕組みなど）は [ルールブック.md](ルールブック.md) にまとめてあります。

---

## 2. 運営する側の人向け

### 参加者名簿を用意する（`members.txt` → Issue自動作成）

1. `members.txt` に、参加者の名前を1行に1人ずつ書く（スペース不可、名前の重複不可）
2. `node sim/sync-members.ts` を実行する
3. `members.txt` にいて、まだIssueが無い人だけ、自動でIssueが作られ `players.json` が更新される

何度実行しても安全です（既にいる人には何もしません）。シーズンごとにメンバーが変わるときは、`members.txt` を書き換えてこれを実行するだけです。`members.txt` から名前を消しても自動では削除されません（間違って抜けを消さないための安全策）。抜けた人は `players.json` から手で消してください。

**今のところ、シーズンの途中から1人だけ合流する仕組みはありません。** 世界は最初に決めた参加者全員分をまとめて作る作りになっているためです。参加者を増やしたいときは、上の手順で `players.json` を更新してから、次のシーズンを `node sim/reset-season.ts` で始めてください。

### シーズンをリセットする

```bash
node sim/reset-season.ts
```

今の進行状況を消して、新しい地図で0ターン目から作り直します。確認をとってから実行されるので、間違って実行しても `y` と答えない限り何も壊れません。全参加者のIssueに開始のお知らせが投稿されます。

### 手動でターンを進める（部会などで）

GitHubの「Actions」タブ →「世界を1ターン進める」→「Run workflow」で、いつでもその場で1ターン進められます。部会でプロジェクタに盤面を映しながら使うと盛り上がります。

### 自動実行の仕組み

`.github/workflows/turn.yml` が1日4回（9/13/17/21時JST）自動的に `node sim/github-turn.ts` を実行し、変更を `game/` フォルダにコミットします。**GitHubの定時実行は混雑時に数十分ずれることがあります。** 「9時ぴったり」を前提にしないでください。

## 3. 手元で動かす（バランス検証・改造したい人向け）

### Node.js を入れる

<https://nodejs.org/> を開いて、**LTS** と書かれているほうをダウンロードして、案内どおりに進めるだけです。バージョンは **22以上**が必要です（TypeScriptを追加インストールなしで直接実行しているため）。

```bash
node -v
```

`v22.x.x` のような表示が出れば成功です。`npm install` は不要です（外部ライブラリを一切使っていません）。

### ボットでバランスを検証する

```bash
node sim/run.ts
```

30人・4ターン/日・4週間（112ターン）を想定したシミュレーションが数秒で走ります。ボットは3種類（`trader`＝普通に交易、`loner`＝誰とも取引しない、`betrayer`＝都合が悪くなると契約を切る）で、実行すると型ごとの平均得点とバランス診断が出ます。出力は `out_test/` に保存されます（本番の `game/` とは別物です）。

### 自分1人＋ボット4人で試し打ちする

```bash
node sim/solo.ts
```

`commands_solo.json` に自分（p00）の命令を書いてから実行してください。他の4人は自動でボットが動きます。出力は `out_test/` とも `game/` とも別の `out_solo/` です。

### 手元だけで1ターンずつ進める（GitHubを使わない練習）

```bash
node sim/step.ts
```

`commands.json` に命令を書いて実行、を繰り返します。書き方は [commands_書き方.md](commands_書き方.md)（JSON形式）を見てください。

## 4. 数字をいじって遊ぶ

**バランス調整用の数値はすべて `src/config.ts` に集めてあります。** ここ以外の場所に数字を書き散らかさないのが、あとで自分を助けます。いじって `node sim/run.ts` を打ち直すだけで、すぐ結果が変わります。

### 実験1: 資源のかたまりを増やす

```ts
clustersPerResource: 1,  →  3 に変える
```

資源が細かくばらけて、各プレイヤーが自力で3種そろえられるようになります。結果、交易しなくなってゲームが死にます。「資源をわざと偏らせる」がなぜ生命線なのかが、数字で体感できます。

### 実験2: 建設コストを下げる

```ts
buildCostBase: 10,  →  5 に変える
```

全員がすぐ最大レベルに到達して、やることがなくなります。長期戦にならない。

### 実験3: 人数を変える

`sim/run.ts` の先頭にある `PLAYER_COUNT` を書き換えます。**人数を変えると結果がまるで違います。** 本番の人数で必ず検証してください。人数を増やすなら `mapWidth` / `mapHeight` も広げる必要がありますが、**地図を人数に比例して縮めるとかえってバランスが崩れることがあります**（資源のかたまり同士の距離が近くなりすぎるため）。人数を減らすときは、まず地図はそのままで `tradeRange` を広げる方から試すのがおすすめです。

## 5. ファイルの役割

```
src/
  types.ts        データの形の定義だけ。処理は書かない
  config.ts       バランス調整用の数字を全部ここに集約 ← まずここをいじる
  rng.ts          種を与えると毎回同じ結果になる乱数
  worldgen.ts     世界を最初に作る（資源のかたまり・川・飛び地を配置）
  rules.ts        ★ ゲームの心臓部。1ターン分の処理
  render.ts       世界をSVG画像にする

sim/
  bots.ts           検証用のボットの判断ロジック
  run.ts            ボットで112ターン回してバランスを見る（出力: out_test/）
  solo.ts           自分1人+ボット4人で試し打ち（出力: out_solo/）
  step.ts           手元のcommands.jsonで1ターンずつ進める（出力: out/）
  commandInput.ts   命令の検証（step.ts・solo.ts共通）
  commentParser.ts  GitHub Issueの一行コメント→命令 の変換
  github.ts         GitHubのIssue・コメントを読み書きする最小限の部品
  github-turn.ts    本番: Issueのコメントを読んで1ターン進め、結果を返信する
  worldBootstrap.ts 0ターン目の世界を作る共通処理
  reset-season.ts   シーズンをリセットする

.github/workflows/turn.yml   1日4回の自動実行 + 手動実行ボタン
index.html                    盤面ビューア（GitHub Pagesで公開）
game/                         本番の進行状況（Gitでコミットされる本物の save）
players.json                  参加者ID → Issue番号 の対応表
```

### 設計で守っていること

**`rules.ts` はGitHubのことを一切知りません。** ただデータを受け取ってデータを返すだけの関数です。だから手元で一瞬で100ターン回せます。もしここにGitHubを呼び出すコードを混ぜてしまうと、1ターン試すのにネットワーク通信が必要になり、検証速度が数百倍遅くなります。**「ゲームのルール」と「GitHubとのやりとり」を絶対に混ぜない。** `sim/github-turn.ts` は入出力の皮をかぶせているだけで、中身の判定は全部 `rules.ts` に任せています。

**乱数に `Math.random()` を使っていません。** 種から計算する自前の乱数（`rng.ts`）を使っています。同じ入力なら必ず同じ結果になるので、リプレイの再生や検証ができます。

## 6. 今のバランス

30人・4ターン/日・4週間（112ターン）のボット検証で、6項目中5〜6項目が `[OK]` になる設定まで調整済みです（`node sim/run.ts` で再現できます）。交易型が孤立型より明確に強く、裏切り型は長期的に損をします。唯一安定しないのが「都市Lv1のまま伸び悩む人の割合」で、地図サイズや `tradeRange` の調整でかなり改善しましたが、完全には無くせていません。実際の人間でシーズンを回してみて、本当に問題になるかを見るのが次の一歩です。

対策の候補は次の3つです。

1. **序盤だけ資源を配る**（最初の数ターンは全員に補助金）
2. **同盟・ギルド制**を入れて、新人が既存グループに入れるようにする
3. **不利な人ほど生産にボーナス**（マリオカート方式）
