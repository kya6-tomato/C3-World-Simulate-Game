# 非同期永続世界ゲーム — 第0段階（エンジン）

まだGitHubは使いません。**手元で世界を100ターン回して、ゲームとして成立しているかを確かめる**ためのプログラムです。

---

## 1. 動かすまで（5分）

### Node.js を入れる

<https://nodejs.org/> を開いて、**LTS** と書かれているほうをダウンロードして、案内どおりに進めるだけです。

> **バージョンが22以上である必要があります。** このプロジェクトはTypeScriptを追加インストールなしで直接実行しているためです。

### 入ったか確認する

「ターミナル」（Windowsなら「PowerShell」）を開いて、こう打ちます。

```bash
node -v
```

`v22.x.x` のような表示が出れば成功です。`command not found` と出たら、パソコンを再起動してからもう一度試してください。

### 実行する

このフォルダの場所までターミナルで移動します。移動は `cd` （change directory）というコマンドです。

```bash
cd ダウンロードした場所/world-game
node sim/run.ts
```

> フォルダのパスがわからないときは、`cd ` と打ってから **フォルダをターミナルの窓にドラッグ＆ドロップ** すると、パスが自動で入力されます。

`npm install` は必要ありません。外部ライブラリを一切使っていないからです。

## 2. 何が起きるか

**部員50人・4ターン/日・4週間（112ターン）** を想定したシミュレーションが数秒で走ります。

ボットは3種類います。`trader`（普通に交易する）、`loner`（誰とも取引しない）、`betrayer`（都合が悪くなると契約を切る）。実行すると、型ごとの平均得点が出ます。

```
型ごとの平均得点:
  trader    人数 38  平均得点   63.6  平均信用 100
  betrayer  人数  7  平均得点   43.3  平均信用  75
  loner     人数  5  平均得点   37.6  平均信用 100
```

**交易する人が、孤立する人の約1.7倍の成績を出しています。** そして裏切り者は、短期的には得をするのに長期では誠実な人に負けている。これがこのゲームで狙っていた力学そのものです。

続けて診断が出ます。

```
--- 判定 ---
  [OK] 交易が全体の96%のターンで発生している
  [OK] 交易型が孤立型より明確に強い（平均 64 vs 37）
  [OK] 裏切り型が長期的に損をしている（誠実 64 vs 裏切り 43）
  [要調整] 18/50人が112ターンかけて都市Lv1のまま
  [OK] 全員に交渉できる隣人がいる
  [OK] 成長が頭打ちになっていない
```

**現状は6項目中5項目クリアです。** 残る1つ（伸び悩む人が多い）については第6章に書きました。

### 出力されるファイル

実行すると `out/` フォルダに3つできます。

| ファイル | 中身 |
|---|---|
| `out/map.svg` | 最終ターンの地図。**ブラウザにドラッグすると開けます** |
| `out/state.json` | 世界の状態まるごと。将来これがGitHubに置かれる |
| `out/history.json` | 毎ターン何が起きたかの記録 |

まず `out/map.svg` を開いてみてください。資源が3つの地域にくっきり分かれていて、プレイヤーの領土が枠線の色で表されています。

## 3. 数字をいじって遊ぶ

**バランス調整用の数値はすべて `src/config.ts` に集めてあります。** ここ以外の場所に数字を書き散らかさないのが、あとで自分を助けます。

いじって `node sim/run.ts` を打ち直すだけで、すぐ結果が変わります。おすすめの実験を3つ。

### 実験1: 資源のかたまりを増やす

```ts
clustersPerResource: 1,  →  3 に変える
```

資源が細かくばらけて、各プレイヤーが自力で3種そろえられるようになります。結果、**誰も交易しなくなってゲームが死にます。** 判定が `[要調整]` に落ちるはずです。

「資源をわざと偏らせる」がなぜ生命線なのかが、数字で体感できます。

### 実験2: 建設コストを下げる

```ts
buildCostBase: 12,  →  5 に変える
```

全員がすぐ最大レベルに到達して、40ターンあたりでやることがなくなります。長期戦にならない。

### 実験3: 人数を変える

`sim/run.ts` の先頭にある `PLAYER_COUNT` を書き換えます。

```ts
const PLAYER_COUNT = 50;  →  20 や 80 に変える
```

**人数を変えると結果がまるで違います。** 5人で完璧にバランスが取れていた設定が、80人にすると壊れました（実際そうなりました）。本番の人数で必ず検証してください。

人数を増やすなら、`mapWidth` / `mapHeight` も一緒に広げる必要があります。目安は **1人あたり16マス前後**です。

### 実験4: 外交を有料にしてみる

`src/rules.ts` の `ECONOMIC` に `"offer"` を追加すると、交渉が手番を消費するようになります。

すると**交易型が最下位に転落します。** 交渉するほど開発が遅れるからです。「話し合いにコストをかけさせると、話し合わない人が勝つ」——設計で最も苦労した部分がここでした。

## 4. ファイルの役割

```
src/
  types.ts      データの形の定義だけ。処理は書かない
  config.ts     バランス調整用の数字を全部ここに集約 ← まずここをいじる
  rng.ts        種を与えると毎回同じ結果になる乱数
  worldgen.ts   世界を最初に作る（資源をかたまりで配置）
  rules.ts      ★ ゲームの心臓部。1ターン分の処理
  render.ts     世界をSVG画像にする

sim/
  bots.ts       検証用のボットの判断ロジック
  run.ts        100ターン回して結果を表示する
```

### 設計で守っていること

**`rules.ts` はGitHubのことを一切知りません。** ただデータを受け取ってデータを返すだけの関数です。だから手元で一瞬で100ターン回せます。

もしここにGitHubを呼び出すコードを混ぜてしまうと、1ターン試すのにネットワーク通信が必要になり、検証速度が数百倍遅くなります。**「ゲームのルール」と「GitHubとのやりとり」を絶対に混ぜない。** これが後の工程を楽にする一番のポイントです。

**乱数に `Math.random()` を使っていません。** 種から計算する自前の乱数（`rng.ts`）を使っています。同じ入力なら必ず同じ結果になるので、「昨日のターンを再計算して検証する」「リプレイを再生する」ができます。

## 5. サークル運用の設計（決定済み）

### ターンの時刻

1日4ターン、夜間は動かしません。

| 日本時間 | 9:00 | 13:00 | 17:00 | 21:00 |
|---|---|---|---|---|

GitHubの定時実行はUTC基準なので、cronにはこう書きます。

```yaml
on:
  schedule:
    - cron: "0 0,4,8,12 * * *"   # JST 9/13/17/21時
  workflow_dispatch:              # 部会用の手動実行ボタン
```

**GitHubの定時実行は混雑時に数十分ずれます。** 「9時ぴったり」を前提にした設計にしないでください。

### 金曜の部会

`workflow_dispatch` を入れておくと、ボタンひとつでその場でターンを進められます。部会でプロジェクタに地図を映して、その場で交渉させて、5ターン一気に回す——これが一番盛り上がる遊び方になるはずです。

平日は各自がスマホでぽちぽち、金曜は全員で盤面を囲む。この二層構造が週1サークルには合っています。

### 命令の受け取り方

**1人1つの専用Issueを立てて、そこにコメントで命令を書いてもらう形にします。**

新しいIssueを毎回立てさせると、50人×4ターン×1日 = 1日200件でIssue一覧が壊滅します。1人1スレッドなら、Issue一覧がそのまま参加者名簿になり、結果報告も同じスレッドに投稿できて、`@ユーザー名` の通知がそのままスマホに届きます。

### 命令を出さなかったとき

1日4回も入力させるのは苦行なので、**常設命令**（`standing`）を用意しました。命令がないターンは自動的にそれが実行されます。放置していても最低限は成長するので、テスト期間中に全滅する事故が防げます。

### シーズン制

112ターン = 4週間で1シーズンにするのがおすすめです。抜け穴が見つかっても次で直せますし、途中参加した人が「もう手遅れ」にならずに済みます。

## 6. まだ解決していない問題

**50人中18人が、112ターンかけて都市レベル1のままです。** 判定でも `[要調整]` が出ます。

原因は交渉相手が見つからないことですが、**これはボットが馬鹿だからという可能性が高い**と見ています。今のボットは「余剰が一定量を超えたら、条件の合う相手を1人だけ探す」という単純な判断しかしません。人間なら、条件が悪くても交渉しますし、断られたら別の人に持ちかけます。

とはいえ本番で同じことが起きたら18人が辞めるので、対策は必要です。考えられる手は3つ。

1. **序盤だけ資源を配る**（最初の20ターンは全員に補助金）
2. **同盟・ギルド制**を入れて、新人が既存グループに入れるようにする
3. **不利な人ほど生産にボーナス**（マリオカート方式）

3が一番効きそうですが、まずは実際の人間で1シーズン回してみて、本当に問題になるかを見るのが早いと思います。ボットの予測が外れる可能性は十分あります。
